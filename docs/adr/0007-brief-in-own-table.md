# 归纳产物单独建表，明确排除在归纳输入之外

## 状态

已采纳（Accepted）——依据：正文三条决策（简报单独建表、恒被排除在归纳输入之外、不进 `board` 不参与接续注入）无反转记录，且被 ADR-0009 当作边界约束沿用（ADR-0009 决策第 6 条标题即「边界：判断型关系独立存，守 ADR-0007 三条」，其 Considered Options 里又有「关系存进 `notes`：被否（沿用 ADR-0007 三条理由）」）；本件的「简报是二手摘要、不是事实契约」定调已进 GLOSSARY.md「归纳」小节（现工作区未提交改动新增），属采纳而非观望。**尚未实施**：`src/store.ts` 的 `boardSpec` 只有 threads/notes/links 三表，无 `timelines` 表，src/ 里也没有任何简报/归纳实现（`src/client/index.ts` 中出现的 `hb-timeline` 只是竖向时间线的 CSS 类名，与本件的 Brief 无关），本件 Consequences 要求的 `board` 输出「基于 N 条，此后新增 M 条」新鲜度行在 `src/tools.ts` 里也不存在。两点须知：①本件引用的 ADR-0006 原话「`extractMaterial` 显式跳过 `source.kind === 'plugin'`」已因 DSH 0.1.7-rc.1 移除该 kind 而改为「只认 `kind === 'user'`」（commit `db1dd28`），先例仍然成立但措辞过时；②`docs/maintenance-decision-2026-09-25.md` §6「冻结不做」把 ADR-0007/0008 的工作区 Brief 列为冻结项，属排期建议而非决策推翻，需用户确认是否改标。

工作区简报（Brief）落独立表（`timelines`），**不进** `notes`。

若把简报当成一条交接条存进 `notes`，它会自食其果：下一次归纳的输入是「当前工作区的全部交接条」，于是简报被当成输入再总结一遍——正是 ADR-0006 记录的复读膨胀（874 字 → 2290 字）换个位置重演，**且每重算一次就长一层**。同一条还会带来两个连带后果：出现在 `board` 清单里（模型分不清真条与归纳结果）；可被接续注入，从而变回事实契约，与「简报是二手摘要」的定调直接冲突。

## 决策

- 简报存独立表，与 `notes` 并列；它是**缓存而非账本产物**——随时可弃、可重算。
- **明确排除在归纳输入之外**：归纳工人的输入恒为「当前工作区的交接条」，不含任何简报。
- 不进 `board` 输出、不参与接续注入。

## Considered Options

- **存进 `notes`，作为特殊类型的条**：被否——上面三个后果全中。
- **不落库、只存进程内存**：被否——dsh-web 重启即丢，每次重启重付一次几十秒的 LLM 成本。

## Consequences

- 做法在插件里有先例：ADR-0006 的 `extractMaterial` 显式跳过 `source.kind === 'plugin'`，防注入全文被再总结。同一招，只是过滤条件从「插件注入的消息」换成「归纳产物」。
- 简报的新鲜度必须**显式表达**（`board` 输出带「基于 N 条，此后新增 M 条」），因为它不再能靠「有没有这条 note」推断。
