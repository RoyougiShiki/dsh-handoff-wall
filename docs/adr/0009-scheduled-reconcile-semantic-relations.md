# 定时对账派生摘要关系：片段级语义关联，不做交互绑定

## 状态

已采纳（Accepted）——依据：本件开头自述「定稿」，是 09-25/09-26/09-28 三轮讨论的收敛结果，全篇无「待拍板／未决」字样（唯一自记的未完成项是 Consequences 首条的「ADR-0001 需要一条修订说明……**待补**」），也没有更晚的 ADR 指它；它推翻的是 ADR-0008 的「触发」一条（Consequences 第 2 条），其余各件均按「沿用」处理。**尚未实施**：src/ 无判断型关系表、无对账器（`ctx.interval` 全仓零命中，`src/store.ts` 的 `boardSpec` 仍只有 threads/notes/links 三表），本件 Consequences「`inject` 需加 `timer`」一条要求的改动也未做（`src/index.ts` 的 `inject` 数组无 `timer`）。落地前还须处理两件事：给 ADR-0001 补那条修订说明；以及与 `docs/maintenance-decision-2026-09-25.md` §0「冻结功能，只做 DSH 兼容与正确性修复」的排期冲突（该建议在 09-25，本件成文于 09-29，这层先后与取舍没有在 ADR 里显式记录）。

本 ADR 定稿「摘要关系日志」的落地方案。它是 09-25 / 09-26 两轮讨论经 09-28 复核后的收敛结果，前置决策见 ADR-0001 / 0003 / 0005 / 0006 / 0007 / 0008。

## 背景与问题

用户需求（09-28 原始表述）：

- 每个对话有按规定格式的文本摘要 —— **已有**（六段交接条）
- 能知道对话有没有归档 —— **已有**（ADR-0003 实时同步宿主 live/persisted）
- AI 可以自己查看这些摘要 —— **已有**（`board` / `read_handoff`）
- 工作区内多对话之间，时间顺序和摘要内容的关系能整理出来 —— **顺序已有，关系缺**
- 类似摘要关系日志，可以查看和维护 —— 缺「关系」
- 查看维护机制参考记忆系统 —— 缺「自动维护」
- 和一般看板不一样，不需要人工逐个处理编辑
- 和普通记忆也不一样
- 工作区内对话除了摘要内容之间的关系，还有直接的关系，以及时间顺序

**调研结论（09-28，一手核实）**：生态里没有任何插件能整套替代。各候选各占一半——

| 候选 | 有的 | 缺的 |
|---|---|---|
| `dsh-session-flow`（4★ Apache-2.0） | 会话档案、归档、折叠时间线 | 无跨会话关系账本 |
| `benz-ai-x/dsh-research-graph`（6★ MIT） | 会话是图节点、Branch/Merge、Session Digest | **关系靠人工触发**；只有分叉/汇入两种事实型关系；无片段级关系；不表达归档 |
| `adoresever/graph-memory`（631★ MIT） | **先摘要后派生 SPO**、导航层/事实层分离、LPA+PPR | 节点是**轮**不是会话；关系是**实体关系**不是叙事关系；目的是召回省 token |
| `@modusensus/dsh-mneme`（MIT） | 实体/属性/时间轴三层、autoDream 巩固 | 对象是**知识点**；autoDream 会**重写**内容 |
| `meow-memory`（126★ MIT 0 依赖） | **空闲定时触发 + 幂等抢占 + 归档跳过** | 对象是记忆条目，不是会话摘要 |
| Hindsight（40k★ MIT） | 变化记录（"以前 X 后来 Y 因为 Z"）、整体是渲染 | **重**（13MB + 5 依赖 + 要 Python 服务）；DSH 适配层 npm 仍 0.7.0，v4 修复未发版 |

**关键空白**：会话语义关系无人做；记忆插件的语义关系作用在**实体**上，会话作为主体的身份已丢失。

## 决策

### 1. 关系粒度是「片段级」，不是「摘要整体之间」

这是本 ADR 相对 09-26 讨论的**核心修正**。关系不建在「条 A ↔ 条 B」上，而建在**六段内部的具体条目之间**：

```
条 A 的第 3 段某条决策  ←──关系──→  条 B 的第 2 段某个产物
条 A 的「下一步」某方向 ←──关系──→  条 C 的「已完成」某项
```

理由：
- 一条摘要覆盖一整个会话，粒度太粗——「A 和 B 相关」这种判断几乎无信息量。
- **片段的粒度才可能被人工核对**，而人工**不可能**去勾「A 条第 3 段和 B 条第 1 段有关」——所以**只能靠 LLM 语义判断，不能靠交互触发绑定**。这是用户明确的裁决：**顺序和关系要靠智能语义建立，不应该靠交互触发绑定。**

### 2. 关系必须来自语义判断，不接受交互绑定

- **不接受**：人工点选、`Branch`/`Merge` 式动作绑定（`research-graph` 的做法）。
- **接受**：定时对账后，由 LLM 读两边**片段内容**判断关系。
- **注意区分**：现有 `links` 表（ADR-0006）是**事实型**接续血缘（"B 从 A 接续"），**保持不变**，不是本 ADR 的关系来源。两者是两类东西：
  - **事实型**：不可变历史事件，有就有、没有就没有，可被接续注入
  - **判断型**（本 ADR 新增）：LLM 解读，可错、可被推翻、**不可进 `board`、不可参与接续注入**

### 3. 触发 = 定时对账，不判断「会话结束」

**已核实：DSH 没有「会话结束」这个概念**，该信号不可得：

- `session/disposed` 的语义是「从活动注册表移除」（`detachEntered` → `emitDisposed`），浏览器关闭、用户走开、进程被杀都不触发；`dsh-app-boot` 的退出路径是 `proc.exit(1)` 直接走，不保证 drain。
- `session/end-seed` 只用于 fork 时标记继承前缀切点，与会话结束无关。
- 会话只有 live/persisted 维度，**归档是另一维度**（ADR-0003）。

**因此改为周期对账（状态比对，而非事件流）**：

```
ctx.interval(每日一次)
  └─ ctx.sessionQuery.listSessions()          // newest-first，只读元数据
  └─ 与上次存档比对 lastSeq / 最后活动时间
       ├─ 没变 → 跳过（零成本）
       └─ 变了 → 入队；待攒够阈值后重算该会话摘要
  └─ 写回存档（幂等，随时可重跑）
```

**这个设计的优点**：天然幂等、天然可续跑。关机、重启、`systemctl --user restart dsh-web` 都只是「下次对账时补上」，不存在漏触发。存档带 `lastRunAt`，启动时发现距上次对账超期则立即补跑一次。

**明确不用的钩子**：`agent/pre-step`。它在发送路径上（waterfall，返回 `PreStepDecision`），有 OpenViking 实测把用户发送延迟 300–2000ms 的前车之鉴。

### 4. 三个固定参数

| 参数 | 取值 | 理由 |
|---|---|---|
| 对账周期 | **每天 1 次** | 只读元数据，成本极低；后续可调 |
| 摘要重算阈值 | **新增 ≥ 5 轮** | 低于此只记账不动摘要，避免摘要抖动 |
| 可定稿判据 | 会话 ≥ 24h 无新事件 | 抄 `meow-memory` 的「最后发言晚于上次 dream」 |

### 5. 一批变了就批量处理，不逐条触发

用户裁决：**「如果多好几个会话都更新摘要了，那就是等都更新完了，最后一遍顺序和关系更新即可。这都是一轮 LLM 更新而已，也不需要很多次。」**

即：摘要是**逐个**重算（各会话独立），关系是**攒批后统一**更新一次。不做 N² 逐对比较；用「最近 K 条 + 粗筛」缩小候选，只有粗筛命中的片段对才进 LLM 精判。

### 6. 边界：判断型关系独立存，守 ADR-0007 三条

判断型关系与工作区简报（Brief）同性质——**是解读，不是事实契约**。因此：

- 落**独立表**，不进 `notes`（否则自食其果：下一轮归纳输入会把它当条再总结）
- 不进 `board` 输出（模型分不清真条与解读）
- **不参与接续注入**（二手摘要变回事实契约）
- **可重算、可废弃**（缓存而非账本产物）
- 每条带 `valid_at` / `invalid_at`（Graphiti 式生命期）+ 证据（依据的条号与片段）+ AI 理由
- **必须显式标注「这是 AI 判断」**，与事实型 `links` 在输出上可区分

### 7. 摘要格式与存量完全不动

六段契约、47 条存量、`board`/`read_handoff`/`write_handoff`/`who_else` 四工具、关联板界面、`links` 表——**全部不改**。

本 ADR 只新增：**一张关系表** + **一个定时对账器**。顺序沿用既有 `createdAt` / 会话时间戳，不新建。

## 参考源与取用方式

**原则：按实际需求取用，不无脑抄。**

| 参考源 | 取用 | 不取用 |
|---|---|---|
| **`meow-memory`** | ⭐ 定时触发骨架：`idleMinutes` 可配、空闲判据、DB 原子节流 + `dream_pending` 幂等抢占、无 live agent / 已归档会话跳过、长期稳定内容不反复重审、手动命令兜底 | 七层记忆结构、注入机制（本插件不做注入） |
| **`graph-memory`** | ⭐ **「先摘要、再从同一次摘要派生关系」**（明确要求**不要拆两次 LLM 调用**）；导航层/事实层分离；校验失败隔离不污染；重复 SPO 形成证据强度而非自造置信度 | 轮级粒度、SPO 实体关系、接管模型可见上下文（本插件明确不接管、不注入） |
| **Hindsight** | "以前 X，后来 Y，因为 Z"的变化记录写法；「整体是渲染、可删可重建」 | **不装**——重（13MB + 5 依赖 + 要 Python/uv），且 DSH 适配层 npm 仍 0.7.0、v4 修复未发版。**只读文档取思想** |
| **`research-graph`** | 摘要「**只读投影**」定位；**按源版本缓存失效**（会话有新内容则标「有新内容」而非偷偷改旧摘要） | Branch/Merge 的交互触发绑定（与本 ADR 第 2 条冲突）；Research Topic 组织轴 |

**Hindsight 的定位特别说明**：其机制完善成熟、star 很高（40k★），是公认最有价值的记忆方案之一；**排除它的唯一理由是重（依赖 + Python 服务），不是机制不好**。因此保留为「读文档取思想」的参考源，不因重而连带否定其机制价值。

## Considered Options

- **装现成插件替代**：被否——逐候选核实后无一整套满足（见背景表）。
- **把关系建在摘要整体之间**：被否（用户裁决）——粒度太粗，信息量低。改为片段级。
- **靠 Branch/Merge 式交互触发建关系**：被否（用户裁决）——「不应该靠交互触发绑定」。且人工无法勾选片段对。
- **靠「会话结束」事件触发**：被否——DSH 无此概念，信号不可得（已核实源码）。
- **每轮都重算摘要**：被否——LLM 成本随轮数线性增长，且摘要反复重写。改用阈值。
- **纯手动触发**：被否——违反「不需要人工逐个处理」。
- **挂 `agent/turn-stopping` 做轮级触发**：被否——本质仍是轮级，回到记忆插件范式；且 serial 钩子内不能等 LLM。定时对账更省、更健壮。
- **关系存进 `notes`**：被否（沿用 ADR-0007 三条理由）。
- **给 `links` 加 `valid_at`/`invalid_at`**：被否——`links` 是不可变历史事件（"B 从 A 接续"永不失效），加失效时间无意义。生命期属于本 ADR 新增的判断型关系。
- **读原始对话建关系**：被否（沿用 ADR-0008 裁决）——不读原对话，只读已策展的摘要。片段级关系同理只读摘要内部片段。

## Consequences

- **与 ADR-0001「零后台进程」的关系需说清**：本 ADR 新增一个 `ctx.interval` 定时对账器，形式上是一个后台定时器。但 ADR-0001 否的是「逐轮抄写对话的采集器 + 滚动烧 LLM 摘要」（talkmap 式），本设计**不做逐轮采集、不做滚动摘要**，只在「会话确有变化且已稳定」时付一次 LLM 成本，且**可整轮跳过**。ADR-0001 需要一条修订说明，把「定时对账」与「滚动采集器」区分开——**待补**。
- **ADR-0008 的触发约束被正当地推翻**：0008 写「触发：模型自行决定，不做自动重算」，本质是「靠模型自觉」，而 09-25 调研已用一手证据否掉这条路（claude-code #46050：用户要求从 "relying on Claude to voluntarily check" 改为 system-level hook）。本 ADR 改为宿主定时器驱动，属范围变化导致的正当推翻，非翻案。
- **覆盖率仍是上限**：本 ADR 只解决「如何组织已有条目」，不提高「写条的勤快程度」。dsh-plugins 22%、.dsh 6% 的覆盖率由写入侧决定。此上限需明写，避免做完之后发现迭代史仍断层。
- **`inject` 需加 `timer`**：`cordis-plugin-timer` v1.1.6 已随 `dsh-base` bundle patch 注册（`- id: timer`），web profile 默认可用；插件 `inject` 数组加一项即可。**不需要第三方定时器插件。**
- **可续跑必须落成代码要求**：存档记 `lastRunAt` + 每会话 `lastSeq`，启动时比对补跑。这是本设计在关机/重启场景下的正确性依赖。
- **判断型关系的质量风险**：LLM 判断会错。缓解手段是「带证据 + 带生命期 + 可重算 + 显式标注」四条，而不是「追求一次判对」。**错误关系的代价必须被限制在「显示层误读」内，绝不能影响接续注入或事实契约。**
